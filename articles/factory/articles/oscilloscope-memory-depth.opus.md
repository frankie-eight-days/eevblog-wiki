# oscilloscope memory depth

Memory depth is the number of samples a digital storage oscilloscope can retain in a single acquisition, and it is the third fundamental requirement of a DSO alongside analog bandwidth and sample rate.[13] It determines how long a window can be captured at a given sample rate, and therefore whether fine detail survives a long capture: deep memory allows a single-shot capture to be zoomed into afterwards to recover glitches and fine waveform detail that were never visible on screen at the original time base.[13] Deep memory is particularly valuable for serial protocol debugging on buses such as SPI and I2C, where a long run of traffic must be captured and then examined bit by bit.[13]

## Why depth is the binding constraint

Sample rate and memory depth together set the capture window. For any chosen time base, the record either fits in memory at full sample rate or the scope must reduce the sample rate to cover the span, so insufficient memory shows up as coarse sampling rather than as an error message. A 4-megasample record proved too shallow to resolve the RF packet structure of an emergency beacon transmission, producing visibly poor sampling of the burst.[368] Very short events are the worst case: a photon-counting module emitting a 20-microsecond pulse per event could not be captured across a full one-second window even with a scope's entire 12 megasamples of memory allocated.[869] Narrow spikes behave similarly — at 14K points they simply vanish from the display, and only at around 1.4 megapoints do they appear reliably, though even then the reconstructed spikes read as shorter than their true width.[866] The general rule follows: a transient captured comfortably with deep memory is lost outright when the record is cut back to a few megasamples.[1320]

The same limit governs post-capture zoom. A conventional scope acquires only within the displayed window, out to whatever memory depth is currently set, so there is no data either side of the screen to scroll into.[1311] Taking a single-shot capture at a relaxed time base and zooming in afterwards works only if the memory depth was deep enough to put detail there in the first place.[1235][13]

## Auto memory depth and the update-rate trade-off

Most scopes default to an automatic mode that picks the record length from the current time base, with a manual override available.[655] Auto mode is deliberately conservative because short records are what make high waveform update rates possible. On a Rigol DS1054Z at the fastest time base, auto memory yields only 60 sample points with a single channel enabled.[704] A DHO800 in auto memory stays at 1,000 points until roughly 2 microseconds per division, reaching 128K points at slower settings.[1566] Conversely, deep memory slows the instrument down: an R&S MXO4 running 8.3 megapoints updated sluggishly, and dropping to 100 kilopoints made history replay markedly faster.[1529] A scope working at full memory depth is characteristically slow, and some measurement functions become unavailable while acquiring at ten megapoints that work fine at one megapoint.[869]

The trade-off is not universal. On a Rigol DS2000, forcing memory depth down to the 14K minimum made no difference at all to the roughly 23,500 waveform updates per second the instrument achieved.[617] The practical judgment is to set the record length to maximum unless fast updating is specifically wanted, since correct FFT results depend on having both the memory depth and the time base right.[845]

Memory is also shared between channels. Turning on a second channel halves the per-channel record — 60 points becomes 30 points per channel on the DS1054Z, and a Tektronix 2 Series entry-level MSO halves its allocation as soon as a second channel is enabled.[704][nO09bc5ozng] Because record length is this consequential, continuous on-screen display of the current sample rate and memory depth is a meaningful usability feature, and not all scopes provide it.[704] Older digital scopes displayed memory occupancy and the position of the visible window within the record.[1450]

## Segmented and record modes

Segmented acquisition divides the memory into frames, so the number of frames obtainable is directly proportional to available memory divided by the points per frame.[1566] A DHO800 set to its maximum 10 megapoints yields only seven frames; dropped to 1K points, the same memory yields about 61,000 frames.[1566] A DS1054Z at 12K points can store 5,197 screens of data, which suits a short burst signal repeating once per second.[704] Some instruments carry memory well beyond their published depth specifically to support always-on continuous replay: a LeCroy WaveJet 354 contained 64 megabits total, giving 8 megasamples per chip and, with two chips per channel, 16 megasamples per channel against a specification of 2.5 megasamples per channel single-channel and a banner figure of 5 megasamples interleaved.[790][792]

## Depth in practice: what the memory actually reaches

An important distinction is between the memory the scope claims and the memory a given operation uses. On a Keysight MegaZoom V instrument set to one megapoint at 3.2 gigasamples per second, pressing stop during a free-running acquisition returned only the 32K points on screen; obtaining the full megapoint record required an explicit single-shot capture. The implication is that live measurements are computed on the on-screen 32K subset rather than the full record.[1638] A related behaviour appears in Keysight's digitizer mode with a fixed four-megapoint record, where the instrument refuses to scroll past the end of acquired data; in auto memory depth mode the same scope will pan out and show blank space either side.[1311] Memory depth handling can also be a source of firmware defects — a Rigol DHO800 waveform-disappearance bug reproduced at 25 megapoints was traced to interaction with the memory depth setting.[EVRdTY4LNhg]

Record length also affects displayed noise. Switching from a short record to long memory mode visibly thins the noise band on screen, by at least one pixel of trace width; the instrument in question offered 8K or 16K in normal mode against 512K or 1 megapoint in long memory mode.[601] For this reason, noise comparisons between instruments are only valid at matched settings — comparative measurements are run at the same bandwidth limit, same time base, and the same memory depth, typically one or two megapoints.[1000][1220][1223]

## Historical scale

Low-end scopes of the early digital era shipped with only a couple of kilobytes of sample memory, which was simply what was available at the time.[13] An original Rigol DS1052E came with 16K.[1450] A Fluke combiscope of the same generation carried 8K of digital memory behind a 260 MHz analog front end and 200 megasamples per second, with four-channel models in the series reaching 32K.[1450] Memory depth was already a differentiator at that price point, with competing instruments marketed on having twice the Rigol's depth for around $400.[111] By the point where 1 megasample became attainable, this was regarded as a transformative amount.[13]

Growth since then has been steep. A Tekway DST1102B offered 1 megasample at 1 gigasample per second; a GW Instek GDS-2000A, 2 megasamples at 300 MHz and 2 gigasamples per second; a Uni-T UPO2104CS, 2.8 megapoints.[487][474][1038] A Rigol MSO5000 provided 20 megapoints, an MSO7000 25 megapoints with 100 megapoints available at full option and 5 gigasamples per second, and a Rigol HDO4000 250 megapoints.[1146][CMoBGGqojqs][1501] A Siglent SDS1204X HD paired 200 MHz, 2 gigasamples per second and 12-bit resolution with 100 megapoints, a figure characterised as more than sufficient.[1612] By the $999 350 MHz class, base memory was 50 megapoints with 500 megapoints unlocked by software option on hardware that already contains it, and 100 megapoints appeared even at the $800 entry-level four-channel tier.[1717][ln_XJDPKJlc] On Rigol instruments, the well-known firmware hack unlocked full memory depth along with full bandwidth and decoding options.[1038]

Very high-speed sampling scopes invert the pattern. A 13 GHz, 40 gigasample-per-second instrument used a minimum of 1K points of sample memory and adjusted the record automatically, sustaining the full 40 gigasamples per second across records from 2K points up to 2 and 8 megapoints.[340] At the other extreme, the shallowest useful settings on modern bench scopes are around 10K to 14K points.[1501][617]
