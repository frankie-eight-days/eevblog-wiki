# memory depth

Memory depth, also called record length or storage depth, is the number of samples a digital oscilloscope's acquisition memory holds for a single capture.[1213][1260] Together with the sample rate it fixes how much time a capture spans, so it decides whether a signal is recorded with enough resolution to be believed, and whether there is any data left to examine when the capture is zoomed into.[1311][1213] It is one of the key figures of merit for an oscilloscope, alongside bandwidth and sample rate, and it is one of no fewer than six independent settings a user must understand before a modern digital scope can be driven properly.[383][610]

## Memory depth, sample rate, and time base

The three quantities are locked together by simple arithmetic: the acquired time window equals the memory depth divided by the sample rate.[1311] At 5 GSa/s the interval between samples is 200 ps, so 4 Mpts of memory buys 800 µs of record, and 2 Mpts buys 400 µs.[1311] At 2.5 GSa/s the sample interval is 400 ps and 10 Mpts corresponds to 4 ms.[1311] The consequence is that as the time base is slowed, a scope must either consume more memory or drop its sample rate; a scope with 4 Mpts cannot hold 5 GSa/s at 1 ms per division, whereas 400 Mpts would allow it.[1311]

Because measurement and analysis functions read the acquisition record rather than the screen, memory depth also governs what those functions can see. Some instruments let measurements be gated to the screen, to the full record, or to the region between cursors.[474] Serial decoding may run over the entire record — one implementation decodes across the full 14 Mpts supplied as standard.[11-AQ_E1fz8] Decoding at 12 Mpts across a long capture reveals occasional glitches within a packet stream that a screen-length record would not contain.[704]

## The interpolation and aliasing trap

The most common failure mode is running out of samples at a long time base and mistaking the interpolated result for the signal. All modern scopes apply sin(x)/x interpolation by default, and with too few points across the record it will draw a smooth, plausible, entirely fictitious waveform.[1213] This has nothing to do with bandwidth — reducing the analogue bandwidth to 20 MHz changes nothing, and the artefact appears on a low-frequency square wave.[1213] With 14 kpts a digital signal captured at 50 ms per division is unrecoverable; raising the memory depth, or choosing a faster horizontal setting such as 1 ms per division, restores the real data.[1213] The same demonstration at 1.25 Mpts on an instrument capable of 256 Mpts is cured by moving to 125 Mpts.[1213]

The trap is insidious precisely because the wrong answer looks clean, and a user who is not mentally tracking how many points are in play can spend a long time chasing an imagined probing problem.[1213] The lower the memory depth, the sooner a given signal will alias.[480] Scopes with a genuine automatic memory depth mode do not permit this: the auto mode picks enough memory that aliasing does not occur, and on the Keysight InfiniiVision series sin(x)/x interpolation cannot be enabled or disabled by the user at all — the instrument decides.[797][1213][480]

## The trade-off against waveform update rate

Deeper memory means more data to process per acquisition, and the waveform update rate falls accordingly.[1478][1552] On one instrument the same infrequent event visible at 140 kpts becomes noticeably less frequent at 1.4 Mpts and hard to catch at all at 14 Mpts.[1478] The best update rate obtainable from a Tektronix 2 Series was 18.8 k waveforms per second, at 10 ns per division, 250 points of memory, and normal trigger mode.[1478] Every scope has an optimum determined jointly by sample rate and memory depth.[1220][1529] A thousand-point record can produce fast-acquisition-like behaviour on an ordinary scope, and increasing the memory immediately costs update rate — the waveforms-per-second figure is not magic.[970]

The practical rule Dave Jones applies at the bench is to choose the lowest amount of memory that still resolves the signal, because catching an infrequent event is a matter of statistics and depends on how many acquisitions per second the scope achieves.[1478] Stated directly: "you should choose the lowest amount of memory for the fastest update rate possible for a given time base".[1478] The corollary is equally firm — "Don't always think it's the best thing to actually set your scope to the maximum memory depth."[1478] A minimum selectable depth of 4 kpts is a reasonable compromise between update speed and record length.[487]

There are exceptions in both directions. An instrument whose acquisition architecture is slow enough may show the same update rate regardless of memory depth, in which case there is no reason not to run maximum memory permanently.[480] Conversely, an FFT wants the memory set to maximum unless fast updating matters more.[845] Intensity-graded and persistence displays only reveal modulation artefacts when there is enough data behind them; at 50 kpts the artefacts simply are not there.[792]

## Automatic versus manual memory depth

Two design philosophies exist. One exposes memory depth as a user setting; the other manages it automatically and, in the strongest form, removes the control entirely.[617][1612] The automatic approach optimises the acquisition and displays the best waveform it can without the user having to know what mode the instrument is in, which makes for a markedly better day-to-day driving experience.[617] Against that, an instrument with a manual setting can be left in a state that misleads: with its memory at 1000 samples a Tektronix produces artefact-ridden garbage on a complex modulated waveform, is nearly right at 10 kpts, begins to resolve at 100 kpts, and needs a megapoint before it approaches what a competing scope shows automatically — and 5 or 10 Mpts for a genuinely equivalent trace.[617] Deep memory of that order is not how such a scope would normally be operated, because it is too slow.[617]

Lacking an auto mode is a real deficiency. The Siglent SDS1000X offers 14 kpts, 140 kpts, 1.4 Mpts and 14 Mpts but no automatic selection, so aliasing that a competing auto mode simply prevents must be avoided by hand.[797] Manually forcing the competing scope to 14 kpts reproduces the identical failure, which confirms that the difference lies in the selection policy rather than the hardware.[797] Some instruments remove the fixed-memory option and allow only a fixed sample rate, leaving automatic memory management as the only behaviour — the likely motive being to eliminate a control that confuses users, though the currently selected depth is still clearly displayed.[1612]

Manual control has one clear advantage. Where a scope will not extend a stopped record beyond the screen in auto record length mode, fixing the memory size explicitly can restore that ability.[1311]

Implementation quality varies. Some instruments refuse to change memory depth outside run mode, returning "Function is disabled" when the change is attempted, which is discovered only by trial.[1231][1311] Others cannot change it in stop mode.[1320] One scope reported that one megapoint memory depth was unsupported in the mode it happened to be in, then produced the setting later without explanation.[487]

## Memory the scope will not use

Nominal memory depth and usable memory depth are not the same number. Some architectures allocate points according to the time base regardless of the maximum set: with 200 Mpts manually selected, one scope uses only 20 kpts at a fast time base, and at 500 ps per division delivers just 10 points across the screen.[1311] Reaching the full 200 Mpts requires winding all the way out to 10 ms per division.[1311] By contrast a Keysight with a nominally modest 4 Mpts uses the whole of it at those same time bases.[1312] Four megapoints used fully is worth more than 200 Mpts used at 400 points.[1312]

One cause of this is an always-on history mode that reserves the entire acquisition memory for stored frames — the full 200 Mpts is genuinely in use, but as roughly two thousand frames of 100 kpts each rather than as one deep record.[1312] The allocation is not clearly documented, and the trade-off it imposes is not obvious from the specification.[1312]

Another is a ping-pong buffer, in which the memory is split in two so that acquisition and readout can overlap. This produces different memory depths in run/stop mode versus single-shot mode: in single shot the instrument knows no further acquisition is coming, disables the ping-pong split, and uses the entire memory with 50% pre-trigger and 50% post-trigger data.[1311] Even so, at 10 ms per division the whole 4 Mpts is consumed by the visible screen and nothing remains outside it.[1311]

A scope quoting 128 kpts of storage depth that cannot be zoomed into after stopping is offering a number with nothing behind it.[1260]

## Channel sharing

On instruments that interleave ADCs and acquisition memory between channel pairs, turning on a second channel halves both the sample rate and the memory depth.[797][149] The mechanism is visible in the hardware: two MegaZoom ASICs and their ADC packages each serve two channels, so enabling channels 1 and 2 halves both figures, while enabling 1 and 3 leaves each at full memory and full sample rate.[384] The effect is standard across the market.[797] On a four-channel Rigol, 12 Mpts standard (24 Mpts optional) drops to 6 Mpts with three or four channels active.[704] The underlying part is a single 512 Mbit DDR2 device — 64 MB, or 16 M samples per channel at 8 bits.[674]

## Apparent noise

Memory depth is the principal reason digital scopes are accused of being noisier than analogue ones, an accusation that is not true.[601][610] The more memory depth in use, the more of the signal's high-frequency content is captured and displayed, so the trace thickens.[601] Bandwidth acts the same way, and always did on analogue instruments too.[601] The other contributors are the boxcar average or high-resolution mode, the intensity-graded display, the update rate and the sample rate.[610] Changing memory depth on a running scope visibly changes the apparent noise and brings out the variable-intensity shading.[797] Comparisons between instruments are therefore only meaningful with memory depth held equal — a noise shootout run at 1 MHz, 20 MHz bandwidth limit and 1 Mpts on every scope, with no averaging.[1000][n4NBUruLyoo] Combining a reduced memory depth with boxcar averaging visibly thins the trace by filtering out that high-frequency content.[601]

## Costs of deep memory

Processing a deep record is slow. Statistical measurement on a full 10 Mpts record can crawl to the point of being unusable, while the same measurement at 1 Mpts updates visibly and 5 Mpts is intermediate.[869] Saving a full record to file takes several minutes.[6qjqhnQiQXQ] Serial decoding across 14 Mpts takes on the order of a second per update, which rules out real-time decoding.[11-AQ_E1fz8] Front-panel interaction can stall entirely at long record lengths.[792]

Segmented memory and zone triggering offer a way around a modest memory budget: capturing ten segments of interest at full resolution and navigating between them gives packet-level detail that a single deep record would otherwise be needed for, which is why 4 Mpts is not necessarily a serious limitation in practice.[1220] Segmented memory implementations differ in flexibility between vendors and between model ranges.[383][704] Where memory is genuinely short on an older instrument, peak detect mode should be used so that absolute peaks are not missed between samples — a sensible default when measuring supply ripple and noise.[594]

## Displaying the setting

Continuous on-screen indication of the current sample rate and memory depth is a usability requirement, not a luxury, because it is the only way to confirm the scope is being used properly.[474] Instruments that omit it — showing date, time and a logo instead, or burying the figures in a system status page in the utility menu — force the user to guess.[474][487] The omission recurs across vendors and price points, including instruments with ample unused screen area.[CMoBGGqojqs][l-fuyHCs2Sw] Where it is done well, sample rate and memory depth are always visible and the user always knows where they stand.[703][480]

## Representative figures

Advertised depths span more than three orders of magnitude. A pocket instrument may carry 240 kpts, which is adequate for its purpose, or 128 kpts, which is not when it cannot be zoomed.[1317][1260] A mid-range Agilent 2000 X series held 100 kpts maximum against 2 Mpts standard and 4 Mpts optional on the 3000 X.[149] The 4000X remained at 4 Mpts, unchanged from the 3000X and half the 8 Mpts of the 7000 series whose case it shared.[383] A budget four-channel Rigol shipped with 12 Mpts and an optional 24 Mpts.[704] A 300 MHz Owon offered 1 kpts through 10 Mpts in decade steps.[480] Later Siglent and Rigol models pushed hard in this area, reaching 250 Mpts as standard with 500 Mpts available.[1218] A 2024-era 350 MHz four-channel Rigol carries 500 Mpts maximum against 50 Mpts on its predecessor, alongside a rise from 1.25 GSa/s to 4 GSa/s.[1717] A Uni-T UPO3000 offers up to 70 Mpts.[1231] Memory depth is frequently a paid software option rather than a hardware difference.[369][704]
