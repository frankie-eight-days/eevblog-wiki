I²C, commonly written I2C, is a two-wire serial bus using SCL for clock and SDA for data, with open-drain drivers and pull-up resistors so that up to 127 addressed devices can share the same pair of wires.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup> It matters because it adds sensors, memory, converters, port expanders, display drivers, and power-management parts without consuming extra [[microcontroller]] pins; the closely related SMBus is found in the same class of equipment, including computer motherboards.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup><sup class="cite"><a href="#src-259" title="EEVblog #259 - PSU Rev C Schematic - Part 12">259</a></sup><sup class="cite"><a href="#src-912" title="EEVblog #912 - BM235 Multimeter Reverse Engineering">912</a></sup> Its performance is deliberately modest: the lowest standard speed is 100 kbit/s, but that and the faster grades are sufficient for most sensors and data-acquisition traffic.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup>

## Electrical model and protocol shape

The bus works because devices only drive the lines low; when no device is driving, pull-up resistors return SCL and SDA to the supply rail.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup> A bit-banged implementation therefore has to make its pins high-[[impedance]] rather than push-pull high, since actively driving the line high would not meet the open-drain requirement.<sup class="cite"><a href="#src-9hMsNOwY5AQ" title="EEVacademy #3 - Bit Banging &amp; SPI Tutorial">•</a></sup> Two resistors pulling up to the [[power-rail]] are a recognizable [[schematic]] signature of the interface.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup>

A transaction begins with a start condition in which SDA is pulled low and then SCL is pulled low, after which data is sent.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup> The address field is seven bits, followed by an acknowledge phase, and the data line is released at the end of a data byte so the receiver can acknowledge it.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup> Between address and data blocks the clock can be held low while SDA is allowed to rise, so a software writer routine mainly has to emit start and stop conditions around clocked-out 8-bit bytes.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup> A missing acknowledge is diagnostically meaningful: serial triggers can be armed on start, stop, and missing-acknowledge conditions, and instrument fault logs report events such as no device acknowledging on the bus.<sup class="cite"><a href="#src-149" title="EEVblog #149 - Agilent Infiniivision 3000 X Series Oscilloscope Review">149</a></sup><sup class="cite"><a href="#src-536" title="EEVblog #536 - HP35670A DSA Repair">536</a></sup>

## Speed grades, pull-ups, and signal integrity

I2C had four speed grades until a fifth was added in 2012, with operation reaching the megabit range.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup> A worked sensor example is an unrealistic 32 kHz, 8-bit accelerometer: 256 kbit/s of sample data becomes about 512 kbit/s if half the frame is assumed to be address overhead, still below a 1 Mbit/s mode.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup>

Pull-up value is the main analogue design choice because lower [[resistance]] gives faster edges, while higher resistance saves [[current]] but slows the rising edge.<sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup> A common recommendation is 2.2 kΩ, moving down toward 1 kΩ when the bus must run faster or when more devices add [[capacitance]].<sup class="cite"><a href="#src-1208" title="EEVblog #1208 - Circuit Analysis &amp; Debugging">1208</a></sup> Adding devices increases bus capacitance and changes slew rate enough to miss data bits, so a 10 kΩ pull-up can become marginal with five devices on one bus.<sup class="cite"><a href="#src-259" title="EEVblog #259 - PSU Rev C Schematic - Part 12">259</a></sup> Long traces are tolerable because I2C is not a critical high-speed routing net, but extra capacitance from a long run over a [[ground-plane]] is countered by reducing the pull-up value.<sup class="cite"><a href="#src-1323" title="EEVblog #1323 - PCB Layout Review &amp; Analysis">1323</a></sup> At the extreme, bus capacitance still dominates: very fast claims such as 10 MHz operation make a nominal 2 kΩ-class pull-up potentially inadequate.<sup class="cite"><a href="#src-991" title="EEVblog #991 - Mailbag">991</a></sup>

Slow rising edges are not merely ugly; if a clock input exceeds a maximum rise/fall time such as 500 ns, the result can be metastability, multiple clock pulses, and otherwise unspecified behaviour.<sup class="cite"><a href="#src-1365" title="EEVblog #1365 - Viewer PCB &amp; Circuit Design Review">1365</a></sup> A captured I2C pulse that fails to reach the expected high level is therefore a rise-time/pull-up problem before it is a protocol problem.<sup class="cite"><a href="#src-876" title="EEVblog #876 - NI VirtualBench Review">876</a></sup>

## Typical uses

The bus exists to economize pins: five devices can hang off one SDA/SCL pair, and moving functions from [[spi]] to I2C can free several microcontroller pins.<sup class="cite"><a href="#src-259" title="EEVblog #259 - PSU Rev C Schematic - Part 12">259</a></sup> Choosing an I2C [[lcd]] instead of a parallel display reduces the pin count to the clock/data pair plus a reset line in a typical small design.<sup class="cite"><a href="#src-232" title="EEVblog #232 - Lab Power Supply Design Part 5">232</a></sup> A four-pin expansion header carrying SDA, SCL, power, and ground is enough to attach further devices.<sup class="cite"><a href="#src-238" title="EEVblog #238 - Power Supply Design Part 7">238</a></sup>

Common device classes include RTCs, EEPROMs, temperature and humidity sensors, magnetometers, DACs, ADCs, digital pots, port expanders, [[led]] drivers, and current/voltage/power monitors.<sup class="cite"><a href="#src-C1on-LaIsCA" title="EEVblog #b10000000000 - 1K Micro Magic">•</a></sup><sup class="cite"><a href="#src-912" title="EEVblog #912 - BM235 Multimeter Reverse Engineering">912</a></sup><sup class="cite"><a href="#src-377" title="EEVblog #377 - Mailbag Monday">377</a></sup><sup class="cite"><a href="#src-761" title="EEVblog #761 - Pebble Time Smartwatch Teardown">761</a></sup><sup class="cite"><a href="#src-251" title="EEVblog #251 - Mailbag">251</a></sup><sup class="cite"><a href="#src-1453" title="EEVblog 1453 - Elgato Key Light TEARDOWN">1453</a></sup> A DS1307 RTC can be driven by bit-banged I2C and its [[battery]]-backed [[sram]] can even store small amounts of application data.<sup class="cite"><a href="#src-C1on-LaIsCA" title="EEVblog #b10000000000 - 1K Micro Magic">•</a></sup> I2C EEPROMs expose the usual power, ground, three address pins, write-protect, SCL, and SDA, and are routinely used for [[calibration]] data.<sup class="cite"><a href="#src-912" title="EEVblog #912 - BM235 Multimeter Reverse Engineering">912</a></sup><sup class="cite"><a href="#src-Xg_niU86bhI" title="Wens 540 Handheld Oscilloscope Multimeter Teardown">•</a></sup> A bidirectional current/power monitor with an I2C interface can offer 0.5% accuracy over temperature, 16 programmable addresses, and 0–26 V measurement range.<sup class="cite"><a href="#src-259" title="EEVblog #259 - PSU Rev C Schematic - Part 12">259</a></sup> A PCA9632 LED driver provides 16 channels with 8-bit [[pwm]] and totem-pole outputs rated to 25 mA per LED.<sup class="cite"><a href="#src-1453" title="EEVblog 1453 - Elgato Key Light TEARDOWN">1453</a></sup>

Audio parts often separate control from data: a codec may use I2C to set registers and operating data while using I2S for the audio stream, and the two interfaces should not be conflated.<sup class="cite"><a href="#src-271" title="EEVblog #271 - Zoom H1 Recorder Teardown">271</a></sup> Some RF and radio parts allow a choice of I2C or SPI programming rather than requiring both.<sup class="cite"><a href="#src-1275" title="EEVblog #1275 - Uniden UHF Walkie Talkie Teardowns">1275</a></sup> Secure elements may present an I2C interface while keeping the cryptographic operations and key storage inside the chip rather than sending secrets across the bus.<sup class="cite"><a href="#src-Yky9yQwZALM" title="Shift Cryptosecurity BitBox02 Crypto Hardware Wallet">•</a></sup>

## Implementation and layout practice

A microcontroller does not need a dedicated I2C peripheral; software bit-banging is practical in tens of lines of code.<sup class="cite"><a href="#src-912" title="EEVblog #912 - BM235 Multimeter Reverse Engineering">912</a></sup> Even so, when a hardware I2C peripheral is available on the needed pins, using it is preferable to bit-banging yet another port.<sup class="cite"><a href="#src-238" title="EEVblog #238 - Power Supply Design Part 7">238</a></sup> Bit-banging remains useful when there are not enough serial ports, when multiple devices share the same address and must be placed on separate buses, or when learning the protocol by implementing the algorithm directly.<sup class="cite"><a href="#src-9hMsNOwY5AQ" title="EEVacademy #3 - Bit Banging &amp; SPI Tutorial">•</a></sup><sup class="cite"><a href="#src-fm13tIe5wSc" title="EEVacademy #4 -  I²C (I2C) Bit Banging">•</a></sup>

I2C traces are normally routed after critical clocks and data lines because the bus tolerates length and is not edge-rate critical in the way high-speed interfaces are.<sup class="cite"><a href="#src-1323" title="EEVblog #1323 - PCB Layout Review &amp; Analysis">1323</a></sup> Layout effort should still avoid pointless layer changes and [[via]] counts, since only two wires are involved and simpler routing leaves room for bypass capacitors and priority signals.<sup class="cite"><a href="#src-1323" title="EEVblog #1323 - PCB Layout Review &amp; Analysis">1323</a></sup> Some I2C port-expander or peripheral chips provide internal software-defined pull-ups, making external resistors optional but board-space-consuming.<sup class="cite"><a href="#src-245" title="EEVblog #245 - PSU Design Part 10 - PCB Layout Editing">245</a></sup>

## Debugging and failure modes

Useful instrument support includes triggering on start and stop conditions, missing acknowledges, specific addresses, and data frames, with real-time decode showing address, read/write direction, ACK/NAK, and data bytes.<sup class="cite"><a href="#src-149" title="EEVblog #149 - Agilent Infiniivision 3000 X Series Oscilloscope Review">149</a></sup><sup class="cite"><a href="#src-436" title="EEVblog #436 - Saleae USB Logic Analyser Review &amp; Teardown">436</a></sup> A start-condition trigger is also the practical way to capture intermittent analogue defects such as runt pulses on SDA or SCL.<sup class="cite"><a href="#src-240" title="EEVblog #240 - Power Supply Design Part 8">240</a></sup> A tri-level or otherwise non-binary [[waveform]] is evidence of bus contention rather than normal two-level digital behaviour, and the fault can be isolated to one device even when no addresses are duplicated.<sup class="cite"><a href="#src-240" title="EEVblog #240 - Power Supply Design Part 8">240</a></sup> Widely spaced I2C packets consume deep capture memory, because everything between packets is still sampled.<sup class="cite"><a href="#src-44" title="EEVblog #44 - Part 2 - Logic Analyzer Tutorial">44</a></sup>

A connected SCL/SDA pair is not proof of traffic; some products route the pins through while showing no activity across power-up, shutter events, or normal operation, leaving the bus apparently unused or reserved.<sup class="cite"><a href="#src-670" title="EEVblog #670 - FLIR TG165 Lepton Sensor Followup">670</a></sup> Conversely, assuming a control travels over I2C can waste troubleshooting time when the actual switch is carried back on a dedicated line through jumpers and [[ribbon-cable]].<sup class="cite"><a href="#src-1672" title="EEVblog 1672 - JBL REPAIR: You&#x27;ll never guess the fault!">1672</a></sup>

The bus is also used for authentication and accessory identity, which creates a distinct failure class. A battery pack with SDA and SCL contacts can contain an ID chip, and a replacement lacking the correct ID or spoof can produce an invalid-battery style error.<sup class="cite"><a href="#src-1370" title="EEVblog #1370 - Kindle Paperwhite REPAIR">1370</a></sup> Powering such a device from a source without the I2C identification device can trigger a repair-required state even though the pack otherwise supplies energy.<sup class="cite"><a href="#src-370" title="EEVblog #370 - Kindle Paperwhite Teardown Review">370</a></sup> Where the peripheral side supports a secure key exchange over I2C, replacing it with a simple signal simulator stops being a wiring exercise and becomes substantial reverse-engineering work.<sup class="cite"><a href="#src-1462" title="EEVblog 1462 - Why Dymo Label Printers SUCK!">1462</a></sup>

Philips originated I2C, which is why older Philips silicon and the I²C trademark recur in consumer and instrument hardware.<sup class="cite"><a href="#src-603" title="EEVblog #603 - Gas Sensor Teardown - Dräger Multiwarn II">603</a></sup><sup class="cite"><a href="#src-1450" title="EEVblog 1450- $99 Fluke Combiscope Ebay SCORE!">1450</a></sup>
