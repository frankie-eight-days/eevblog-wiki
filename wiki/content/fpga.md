An FPGA (field-programmable gate array) is a programmable logic chip that comes as close as possible to designing a custom chip from scratch, allowing virtually any digital function to be implemented in a single universal device.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> The defining difference from almost every other chip on the market is that an FPGA has no intended function when purchased: apply power and it does nothing at all until a configuration is loaded into it.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup>

## Architecture and operation

An FPGA contains no [[processor]] unless the designer puts one in; it is a "sea of logic gates" — configurable logic blocks joined by programmable routing, surrounded by sophisticated I/O blocks.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> Structurally, the chip is a series of tiles of programmable logic elements connected together with wires and switches, so that programming the switches and gates turns the chip into any desired digital circuit.<sup class="cite"><a href="#src-8OaZ89TN0fo" title="Guest Video: OpenTechLab - IcoBoard FPGA Experiments">•</a></sup> The I/O blocks support multiple logic-[[voltage]] standards, slew-rate control, and embedded flip-flops and latches for tasks such as driving DDR memory.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup>

Most FPGAs are volatile devices: the configuration is held in [[transistor]] or latch "fuses" that vanish when power is removed, so an external configuration [[flash-memory|flash memory]] is required to reload the design at every power-up.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> This loading takes time — sometimes seconds — so FPGAs are not instant-on devices, and power-up draws a significant surge [[current]] while the configuration fuses are programmed.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> Some families, such as the non-volatile Lattice parts used in the Agilent 34461A [[multimeter]], power up instantly without an external E²PROM.<sup class="cite"><a href="#src-485" title="EEVblog #485 - Agilent TrueVolt 34461A Multimeter Teardown">485</a></sup>

Modern devices integrate far more than the basic logic-block-and-routing fabric. Almost all decent FPGAs include distributed memory or dedicated [[ram|RAM]] blocks that can implement dual-port memory; a typical contemporary part may carry 50 or 100 DSP cores scattered through the fabric.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> Clock infrastructure includes PLLs and digital clock managers that multiply the external reference — a 20 MHz crystal can drive internal logic at a couple of hundred megahertz — along with phase shifting and complex clocking arrangements, at the cost of significant system-level clock-timing complexity.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> Dedicated global clock pins offer faster routing paths than general I/O, and clock signals such as an [[spi|SPI]] clock should be routed onto them; the number of global clock pins is what allows designs with multiple system clocks.<sup class="cite"><a href="#src-193" title="FPGA Implementation Tutorial - EEVblog #193">193</a></sup><sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup>

Manufacturers offer soft processor cores — vendor-specific 8-, 16-, or 32-bit cores such as NIOS that can be placed anywhere in the fabric — because so many users were implementing processors anyway.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> Parts with hard processors, such as the Xilinx Zynq with its dual ARM Cortex-A9 cores alongside Artix FPGA fabric, are more optimized and lower power than soft cores, need no recompilation of the processor with the design, and are guaranteed to work — something never true of user-designed FPGA logic.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup><sup class="cite"><a href="#src-2" title="EEVblog2 #858 - Red Pitaya Extended Cut">2</a></sup> High-end parts also integrate hard Ethernet transceivers and SerDes serial controllers around the soft fabric.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup><sup class="cite"><a href="#src-1018" title="EEVblog #1018 - ZeroPlus Logic Analysers">1018</a></sup>

## FPGAs versus microcontrollers

The compelling advantage of an FPGA is massive parallelism. Where a processor must service pins sequentially, an FPGA with hundreds of I/O pins can drive them all at once, and dedicated logic can process an incoming signal in effectively real time and forward it out another pin — something impossible for a processor working on, say, a 100 MHz input.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> Consequently, duplicating the function of an existing dedicated chip in an FPGA is a waste of money: an FPGA large enough to hold an AVR core costs more than simply buying the AVR.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> FPGAs also cannot match dedicated silicon on [[power-consumption|power consumption]], because the flexibility of millions of logic elements, routing paths, and configuration cells is not optimized for low power.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup>

## FPGAs versus CPLDs and gate arrays

CPLDs are less flexible than FPGAs — fitting even an 8-bit microprocessor core into a CPLD is impractical — but they are faster, lower power, and offer more deterministic internal timing, which is why a design may pair a large FPGA with a small CPLD for timing-critical functions.<sup class="cite"><a href="#src-111" title="EEVblog #111 - Live Show #5">111</a></sup><sup class="cite"><a href="#src-37" title="EEVblog #37 - Rigol DS1052E Oscilloscope Teardown">37</a></sup> FPGA routing is segmented and connected through switch matrices, which increases delay between logic elements compared with more regular structures.<sup class="cite"><a href="#src-1215" title="EEVblog #1215 - $18,000 4K Monitor Teardown From 2001!">1215</a></sup> Historically, one-time-programmable CMOS gate arrays filled a similar role as a rudimentary form of FPGA for semi-custom logic before FPGAs with configurable logic blocks took over.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup><sup class="cite"><a href="#src-833" title="EEVblog #833 - Mailbag">833</a></sup><sup class="cite"><a href="#src-969" title="EEVblog #969 - Vintage $80k NLE Video Editor Teardown">969</a></sup>

## Disadvantages and design challenges

- **Cost.** Small FPGAs exist at a dollar or two but contain few logic blocks; high-end parts cost thousands of dollars each, and parts costing around $10,000 apiece are bought in quantity for applications such as radio-telescope beamforming.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup><sup class="cite"><a href="#src-818" title="EEVblog #818 - Embedded Electronics With Jack Ganssle">818</a></sup>
- **Power.** FPGAs are relatively high-power devices with a startup surge, making them unsuitable for ultra-low-power design.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup>
- **Packaging.** Logic density and pin count go hand in hand; high-density parts come only in large BGAs, and a million-logic-element device in a friendly 44-pin TQFP does not exist.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup><sup class="cite"><a href="#src-4" title="EEVblog #4 - Calculator Design, Mr Bean, &amp; FPGA&#x27;s">4</a></sup> Even a small 0.4 mm-pitch [[bga|BGA]] FPGA can force an entire board down to 4-thou track/space design rules and tiny drill sizes.<sup class="cite"><a href="#src-193" title="FPGA Implementation Tutorial - EEVblog #193">193</a></sup>
- **Complexity.** A single device may ship with dozens of datasheets and application notes covering the logic blocks, I/O, clocking, serial interfaces, DSP cores, and secure boot programming; the design tools are multi-gigabyte downloads, and fitting and timing-optimizing a large design can take days.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup> Complex modern FPGAs can have 50-page documents devoted purely to power-up sequencing and rail bypassing.<sup class="cite"><a href="#src-1512" title="EEVblog 1512 - Why Bypass Your PCB Like THIS?">1512</a></sup>
- **Timing fragility.** Every recompilation re-routes the design, so all internal timing changes with even a small modification; marginal, board-to-board timing failures are a recognized failure mode.<sup class="cite"><a href="#src-58" title="EEVblog #58 - Warm and Fuzzy FPGA Troubleshooting">58</a></sup>
- **HDL difficulty.** The two major hardware description languages, VHDL and Verilog, are not intuitive to engineers trained in sequential languages like C or BASIC, because everything in an FPGA executes in parallel and clock domains must be managed explicitly; poor HDL practice produces race conditions and related faults.<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup>
- **Maintenance.** Migrating an old FPGA design is painful: legacy devices were often [[schematic]]-based rather than written in HDL, modern tools do not accept those schematics, and FPGA documentation is rarely good enough to hand a design to a new engineer without the original designer's involvement.<sup class="cite"><a href="#src-1032" title="EEVblog #1032 Part 5 - John Kenny Keysight Interview">1032</a></sup>

## Power supply, decoupling, and layout

FPGAs demand multiple supply rails: a design may need a 1.0–1.2 V core rail plus several I/O voltages, with larger devices requiring three, four, or even half a dozen different rails such as 5 V, 3.3 V, 2.5 V for PLLs, 1.8 V, 1.5 V, and 1.2 V.<sup class="cite"><a href="#src-193" title="FPGA Implementation Tutorial - EEVblog #193">193</a></sup><sup class="cite"><a href="#src-1679" title="EEVblog 1679 - Why Does a Uni-T AWG Cost $5800? - BOM Cost Analysis">1679</a></sup> Rails sometimes must power up in a defined sequence to avoid problems such as SCR latch-up inside the chip.<sup class="cite"><a href="#src-1691" title="EEVblog 1691 - Uni-T UDP6731 360W Bench PSU REVIEW">1691</a></sup> Rail voltages below 1 V are common on modern parts — 0.75 V cores appear in current designs.<sup class="cite"><a href="#src-1124" title="EEVblog #1124 - Rigol 7000 Oscilloscope Teardown">1124</a></sup>

Power integrity is critical enough that vendors publish dedicated application notes, some around 100 pages, on powering and bypassing their FPGAs, because the devices gulp current at boot.<sup class="cite"><a href="#src-1477" title="EEVblog 1477 - TEARDOWN! - NEW Tektronix 2 Series Oscilloscope">1477</a></sup><sup class="cite"><a href="#src-1307" title="EEVblog #1307 - TUTORIAL: PCB BOM Consolidation">1307</a></sup> Switching at hundreds of megahertz with edge components reaching into the gigahertz range means bypass-[[capacitor]] [[impedance]] rise at high [[frequency]] is a real concern.<sup class="cite"><a href="#src-859" title="EEVblog #859 - Bypass / Decoupling Capacitor Tutorial">859</a></sup> DC performance matters as much as AC decoupling: excessive [[ground]]-path [[resistance]] across even 20 cm of board can drop enough voltage to upset an FPGA, and with modern 0.8–0.9 V core rails the total margin may be only 30–125 mV, while a board carrying half a dozen large FPGAs can draw tens of amps to triple-figure currents.<sup class="cite"><a href="#src-1216" title="EEVblog #1216 - PCB Layout + FPGA Deep Dive">1216</a></sup> Because current draw depends entirely on what logic is loaded, how fast it runs, and how the I/O is configured, consumption is estimated with vendor power-estimator tools rather than read from a [[datasheet]].<sup class="cite"><a href="#src-496" title="EEVblog #496 - What Is An FPGA?">496</a></sup><sup class="cite"><a href="#src-1216" title="EEVblog #1216 - PCB Layout + FPGA Deep Dive">1216</a></sup>

## Use in test equipment and products

FPGAs are the standard acquisition engine in modern oscilloscopes: ADCs stream raw samples into the FPGA, which performs downsampling, triggering, and protocol decoding in hardware, faster than any application-layer software could.<sup class="cite"><a href="#src-PcxEO3fA_Ls" title="Tektronix 2 Series Discussion with Andy Tedd from Tektronix">•</a></sup><sup class="cite"><a href="#src-674" title="EEVblog #674 - Rigol DS1054Z Teardown">674</a></sup><sup class="cite"><a href="#src-1309" title="EEVblog #1309 - Siglent SDS2000X Plus Scope Teardown+Hack">1309</a></sup> Some variation of the Xilinx Zynq appears in nearly every [[oscilloscope]], combining hard ARM cores running Linux with fabric doing the capture work.<sup class="cite"><a href="#src-1545" title="EEVblog 1545 - R&amp;S MXO4 TEARDOWN. The World&#x27;s Fastest Oscilloscope!">1545</a></sup><sup class="cite"><a href="#src-1530" title="EEVblog 1530 - Siglent SDS2000X HD 12 Bit Oscilloscope TEARDOWN">1530</a></sup><sup class="cite"><a href="#src-1042" title="EEVblog #1042 - Siglent&#x27;s $499 SDS1104X-E 4CH Oscilloscope Teardown">1042</a></sup> Cost reduction in cheaper models is often achieved by substituting a smaller FPGA for a premium part such as the Artix-7.<sup class="cite"><a href="#src-1563" title="EEVblog 1563 - New $389 12bit Rigol DHO800 Scope TEARDOWN">1563</a></sup><sup class="cite"><a href="#src-1510" title="EEVblog 1510 - $699 Rigol 12bit HDO1000 Teardown - WOAH!">1510</a></sup> Where an FPGA's fabric cannot sustain the required clock rate — FPGAs resist running past about 250 MHz — [[waveform]] pipelines are split into parallel paths and recombined.<sup class="cite"><a href="#src-1032" title="EEVblog #1032 Part 5 - John Kenny Keysight Interview">1032</a></sup>

In multimeters, FPGAs handle sampling and data formatting: the Agilent 34461A replaced the custom ASICs of the 34401A with a Lattice FPGA implementing the multi-slope IV conversion, a Keysight design uses an FPGA for high-speed delta-sigma ADC processing and FIR filtering, and the Siglent SDM3055 uses a small Lattice MachXO to buffer and forward its 150 readings per second.<sup class="cite"><a href="#src-485" title="EEVblog #485 - Agilent TrueVolt 34461A Multimeter Teardown">485</a></sup><sup class="cite"><a href="#src-1032" title="EEVblog #1032 Part 5 - John Kenny Keysight Interview">1032</a></sup><sup class="cite"><a href="#src-829" title="EEVblog #829 - Siglent SDM3055 Bench Multimeter Teardown">829</a></sup><sup class="cite"><a href="#src-1190" title="EEVblog #1190 - Mailbag Review Bonanza">1190</a></sup> Arbitrary waveform generators pair a large FPGA with fast DDR3 memory to feed multi-gigasample DACs.<sup class="cite"><a href="#src-1679" title="EEVblog 1679 - Why Does a Uni-T AWG Cost $5800? - BOM Cost Analysis">1679</a></sup> Logic analyzers use FPGAs for sample compression, SerDes-based inputs, and real-time protocol decode and triggering.<sup class="cite"><a href="#src-290" title="EEVblog #290 - Mailbag">290</a></sup><sup class="cite"><a href="#src-1018" title="EEVblog #1018 - ZeroPlus Logic Analysers">1018</a></sup><sup class="cite"><a href="#src-207" title="CleverScope USB Oscilloscope - EEVblog #207 (2 of 3)">207</a></sup>

Classic applications include video generation — a small Spartan-3 with an [[sram|SRAM]] framebuffer and a triple DAC forms a complete VGA display, and one FPGA can host multiple VGA cores driving multiple displays — and video processing such as gain, gamma, and color balancing in production switchers.<sup class="cite"><a href="#src-145" title="EEVblog #145 - Agilent LAN/VGA Module Teardown">145</a></sup><sup class="cite"><a href="#src-494" title="EEVblog #494 - Mailbag">494</a></sup><sup class="cite"><a href="#src-WDfzwCXK0mI" title="WEIRD Blackmagic ATEM Mini Fault">•</a></sup> FPGAs appear in lane-keeping and obstacle-avoidance cameras, ultrasound machines, and beamforming radio astronomy, all workloads that demand parallel processing impossible to do sequentially.<sup class="cite"><a href="#src-818" title="EEVblog #818 - Embedded Electronics With Jack Ganssle">818</a></sup><sup class="cite"><a href="#src-1314" title="EEVblog #1314 - Ultrasound Machine Teardown!">1314</a></sup> Even products with a capable main processor sometimes add a small FPGA for glue logic or display assistance, at a cost of a few dollars.<sup class="cite"><a href="#src-761" title="EEVblog #761 - Pebble Time Smartwatch Teardown">761</a></sup>

## Development tools and learning

Vendor toolchains are notoriously complex, and simply getting a blinking [[led|LED]] running from scratch is difficult; loading the vendor's example projects and working backwards from them is the standard way past the initial grief.<sup class="cite"><a href="#src-636" title="EEVblog #636 - FPGA Demo Boards - DE0 Nano">636</a></sup><sup class="cite"><a href="#src-111" title="EEVblog #111 - Live Show #5">111</a></sup> Sub-$100 starter boards such as the Terasic DE0 Nano (Cyclone IV, roughly $80) provide an entry point.<sup class="cite"><a href="#src-636" title="EEVblog #636 - FPGA Demo Boards - DE0 Nano">636</a></sup><sup class="cite"><a href="#src-494" title="EEVblog #494 - Mailbag">494</a></sup> Synthesis tools that once cost $10,000–$12,000 are now free for many devices, and fully open-source toolchains exist for some families — the IceStorm toolchain made the Lattice iCE40 programmable with open-source software, enabling boards such as the IcoBoard Raspberry Pi hat.<sup class="cite"><a href="#src-818" title="EEVblog #818 - Embedded Electronics With Jack Ganssle">818</a></sup><sup class="cite"><a href="#src-8OaZ89TN0fo" title="Guest Video: OpenTechLab - IcoBoard FPGA Experiments">•</a></sup> On debugging, large FPGAs with hundreds of I/O pins produce correspondingly long JTAG boundary-scan serial streams, since every pin's data must be shifted through the chain; FPGA configuration headers are recognizable by their pin count and their proximity and trace routing to the FPGA.<sup class="cite"><a href="#src-499" title="EEVblog #499 - What is JTAG and Boundary Scan?">499</a></sup><sup class="cite"><a href="#src-p-eLu1z7-cs" title="Rigol HDO1000 Serial Boot Capture for Hack + R&amp;S MXO4 play">•</a></sup>

As engineering judgment, the choice between the two dominant vendors matters little in practice — Xilinx and Altera offer similar competing technology, and what can be done with one can be done with the other.<sup class="cite"><a href="#src-89" title="EEVblog #89 - EEVblog Live Screwup">89</a></sup> FPGA knowledge splits naturally between hardware and software disciplines: it is entirely possible to design FPGA boards professionally while barely being able to write VHDL, leaving the HDL to software specialists.<sup class="cite"><a href="#src-83" title="EEVblog #83 - Do You Suck At Hardware Or Software?">83</a></sup>
